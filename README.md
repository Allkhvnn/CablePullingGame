# Перетягивание каната: Битва знаний

Основной режим — онлайн-матч двух людей по ссылке-приглашению. React + TypeScript + Vite на клиенте, Node.js + TypeScript + ws на сервере. Тренировка с ботом сохранена по адресу `/?mode=training`.

## Запуск разработки

Установите зависимости: `npm.cmd install` (или `npm.cmd ci` для версий из lock-файла).

В первом терминале:

```powershell
npm.cmd run dev:server
```

Во втором терминале:

```powershell
npm.cmd run dev -- --port 5174 --strictPort
```

Откройте `http://localhost:5174`. Создайте комнату и отправьте другу показанную ссылку. Если проверяете два места на одном компьютере, используйте разные браузеры или обычное и приватное окно: вкладки одного браузера используют один сохранённый ключ и возвращают вас на ваше место.

Для двух устройств в одной сети открывайте на обоих сетевой адрес компьютера из строки `Network` в выводе Vite, например `http://192.168.1.10:5174`, а не localhost. Ссылка формируется от адреса открытой страницы. Компьютер с сервером должен оставаться включённым; доступ к выбранному порту должен быть разрешён настройками вашей сети.

`localhost` не является общедоступным адресом. Для игры через интернет подготовлена [пошаговая публикация на AWS](docs/DEPLOY_AWS.md). Ресурсы облака создаются отдельно в вашем аккаунте; локальный запуск сам по себе публичного адреса не даёт.

## Сборка и запуск собранной версии

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run build
npm.cmd start
```

`build` проверяет TypeScript, собирает клиент в `dist/` и сервер в `dist-server/`. `start` запускает Node-сервер на `http://localhost:3001`: он отдаёт собранный клиент и обслуживает WebSocket на `/ws`. Это также позволяет играть по LAN-адресу компьютера на порту 3001 без Vite.

Порт сервера задаётся переменной `PORT` (по умолчанию 3001). В разработке `/ws` и `/health` проксируются Vite на 3001; при изменении порта обновите `vite.config.ts`. Для публичного размещения используйте HTTPS с поддержкой WebSocket в reverse proxy: клиент автоматически выберет `wss`. `vite preview` предназначен для просмотра сборки и не заменяет игровой сервер.

В PowerShell используйте `npm.cmd`, если выполнение `npm.ps1` запрещено. В остальных оболочках подходит `npm`.

## Сценарий матча

1. Создатель получает место игрока 1 и публичное приглашение. Друг занимает место игрока 2. Третьему участнику сервер отказывает.
2. Когда оба подключены, сервер запускает отсчёт 3–2–1, затем общий вопрос на 12 секунд.
3. Каждый выбирает ставку 1–3 и вариант ответа и подтверждает, либо нажимает «Отдохнуть». До расчёта виден только факт подтверждения соперником, но не его ход и ставка.
4. Раунд заканчивается, когда приняты оба действия или истёк серверный срок. Пропущенному ходу назначается `timeout`, а не отдых.
5. Сервер единожды вызывает чистую функцию расчёта и присылает одинаковый результат обоим. На раскрытие ответа даётся 5 секунд, после чего начинается следующий вопрос или показывается итог.
6. Реванш начинается только после согласия обоих участников, при наличии обоих соединений. Состояние и принятые действия сбрасываются, вопросы перемешиваются заново.

Ориентация одинакова на обоих экранах: +10 — победа игрока 1 (справа), −10 — игрока 2 (слева). После 12 вопросов решает знак позиции, при нуле — ничья.

## Отключение и личное место

Сервер выдаёт каждому участнику случайный секретный ключ из 32 байтов. Он хранится в localStorage этого браузера для конкретной комнаты. При повторном открытии приглашения с этого устройства клиент автоматически отправляет `resume` и возвращается на своё место.

В интерфейсе также есть личная ссылка с ключом во фрагменте `#key=...`. Её можно сохранить для возвращения с другого устройства. После успешного входа ключ убирается из адресной строки. **Другу отправляйте только публичное приглашение**: личная ссылка предоставляет доступ к вашему месту. Без личного ключа занять уже зарезервированное место нельзя, даже если его владелец отключён. Новое соединение с тем же ключом заменяет старое, а старое теряет право отправлять ходы.

При обнаружении отключения матч ставится на паузу, сервер сохраняет остаток времени и уже принятые действия. На возвращение — 30 секунд. При возвращении обоих таймер продолжает оставшееся время; заменить принятый ход нельзя. Во время паузы действия отклоняются.

Если участник не вернулся вовремя, победа присуждается оставшемуся подключённому игроку. Если на момент истечения срока отсутствуют оба, матч завершается без победителя. Позднее возвращение не меняет итог; участники могут согласовать реванш. Уже определённая обычная победа при отключении не пересматривается.

Разрыв TCP закрывает участие сразу; потеря сети без закрытия обнаруживается ping/pong за 5–10 секунд, после чего начинается 30-секундный срок. Если игрок закрыл страницу ещё в ожидании второго, его место также не освобождается: после истечения срока комната завершится.

## Архитектура

```text
server/
  index.ts              # запуск и остановка Node
  app.ts                # HTTP, WebSocket, heartbeat и ограничения сообщений
  rooms.ts              # комнаты, авторизация, фазы, таймеры и реванш
  config.ts             # время отсчёта, раскрытия и переподключения
  questions.ts          # только серверный банк сетевых вопросов
  rooms.test.ts         # проверки правил сетевого матча
  socket.test.ts        # тесты двух настоящих WebSocket-клиентов
shared/
  protocol.ts           # типы и проверка входящих сообщений
src/
  App.tsx               # основной онлайн-режим или тренировка
  network/
    useRoom.ts          # WebSocket, ключ места и переподключение
    OnlineGame.tsx      # комната, приглашение и серверное состояние
    OnlineQuestion.tsx  # отправка выбора без локального расчёта
    OnlineQuestion.test.tsx
  TrainingApp.tsx       # сохранённый матч против бота
  TrainingApp.test.tsx
  game/
    engine.ts           # прежние чистые функции расчёта
    types.ts            # типы игровой логики
    session.ts, bot.ts  # локальная тренировка
  data/questions.ts     # отдельные вопросы тренировки
  components/           # простые переиспользуемые элементы интерфейса
```

Сервер — единственный источник истины для сетевого матча. Клиент не отправляет позицию, энергию, победителя или самостоятельно назначенный тайм-аут. Роль определяется по соединению и личному ключу, а не полю запроса. Номер матча и раунда отсекает устаревшие команды. Проверяются фаза, энергия, ставка, вариант ответа и отсутствие уже принятого хода.

Старая функция `calculateRound` сохранена: внутри неё `player` соответствует сетевому игроку 1, `bot` — игроку 2. Это только названия полей старого движка, в сетевом режиме бот не участвует.

Снимок состояния строится по явному списку публичных полей. Токены других игроков, банк вопросов и ожидающие ответы в него не включаются. Правильный ответ появляется только в `reveal` после расчёта. Сетевой банк отличается от тренировочного и не импортируется клиентом. Vite запрещает HTTP-доступ к `server/` и `dist-server/`; собранный сервер раздаёт только `dist/`.

В текущей версии комнаты находятся в памяти одного процесса. Перезапуск сервера удаляет их. База данных, аккаунты и несколько серверных экземпляров пока не реализованы. Комнаты без подключений удаляются через час; максимум — 1000 комнат. Сообщения ограничены 4 КБ и 30 сообщениями в секунду на соединение.

## Где менять правила

- `src/game/engine.ts`: `ROUND_DURATION_MS = 12_000`, `MAX_ENERGY = 5`, `WIN_POSITION = 10`, `QUESTION_LIMIT = 12`, функции силы и восстановления, `checkWinner`.
- `server/config.ts`: `COUNTDOWN_MS = 3_000`, `REVEAL_MS = 5_000`, `RECONNECT_MS = 30_000`.
- `server/questions.ts`: сетевые вопросы. Четыре варианта, правильный индекс от 0 до 3. Нужно минимум `QUESTION_LIMIT` вопросов.
- `src/data/questions.ts`: вопросы только тренировки.

После изменения правил обновите ожидаемые значения тестов и соответствующий текст интерфейса. Онлайн-таймер клиент не завершает: он отображает остаток от серверных часов и ожидает следующего состояния.

## Проверки

70 тестов: прежний движок и тренировка, серверные правила, скрытие ответа, повторные/устаревшие/недопустимые действия, полная партия и реванш, третий участник, переподключение, обработка исчезнувшей комнаты после перезапуска, присуждение победы при отключении, настоящий WebSocket-транспорт и блокировка повторной отправки в React.

Дополнительно проверены работа запущенных клиента и сервера через Vite-прокси, одинаковый результат двух независимых соединений и запрет HTTP-доступа к серверным вопросам. Подключённый графический браузер в этой сессии недоступен; интерфейс проверяется React-тестами, сеть — настоящими WebSocket-соединениями.
