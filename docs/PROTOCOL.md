# WebSocket-протокол

Подключение: `/ws` на том же хосте, что и клиент. Формат — JSON, не более 4096 байтов. Типы и runtime-проверка: `shared/protocol.ts`. Один WebSocket может быть связан только с одним местом.

## Клиент → сервер

```json
{ "type": "create" }
{ "type": "join", "roomId": "идентификатор из приглашения" }
{ "type": "resume", "roomId": "идентификатор", "token": "личный 64-символьный hex-ключ" }
{ "type": "action", "matchId": 1, "round": 1, "action": { "type": "answer", "answer": 2, "bet": 3 } }
{ "type": "action", "matchId": 1, "round": 1, "action": { "type": "rest" } }
{ "type": "rematch", "matchId": 1 }
```

`answer` — индекс 0–3, `bet` — целое 1–3. Номера раунда и матча начинаются с 1. Клиент не может прислать `timeout`: его назначает сервер. Поля `seat` или `roomId` в `action` не дают полномочий: роль и комната определяются привязкой соединения. Неизвестные дополнительные поля не используются.

## Сервер → клиент

```json
{ "type": "joined", "roomId": "...", "seat": "one", "token": "..." }
{ "type": "state", "state": {} }
{ "type": "error", "code": "ALREADY_SUBMITTED", "message": "Ваш ход уже принят." }
```

`joined` отправляется только владельцу ключа. Сохраните ключ для `resume`; повторный `join` не возвращает занятое место. Если личный ключ уже используется, новое соединение заменяет старое; старое закрывается кодом 4001 и теряет полномочия.

`state` одинаков для обоих участников и не содержит секретов:

| Поле | Значение |
| --- | --- |
| `roomId`, `matchId` | Комната и текущий матч |
| `phase` | `waiting`, `countdown`, `question`, `reveal`, `result` |
| `serverTime`, `deadline` | Серверное время и срок этапа в миллисекундах Unix; срок может быть `null` |
| `paused`, `remainingMs` | Пауза и сохранённый остаток времени |
| `reconnectDeadline` | Ближайший срок возвращения отключённого участника |
| `players.one`, `players.two` | `occupied`, `connected`, `energy`, `submitted`, `rematch` |
| `round`, `roundsPlayed` | Номер текущего/следующего вопроса (до 12) и количество рассчитанных раундов |
| `position` | Общая позиция; плюс — к игроку 1, минус — к игроку 2 |
| `question` | Только в фазе `question`: `id`, `text`, четыре `options`; без правильного ответа |
| `reveal` | Только после расчёта: вопрос, `correctAnswer`, результат обоих действий и `delta` |
| `winner` | `one`, `two`, `draw` или `null` |
| `reason` | `normal`, `disconnect`, `abandoned` или `null` |

В `reveal.result` поля старого чистого движка `player` и `bot` означают игроков 1 и 2. Каждое содержит `action`, `force`, `energy`. `timeout` может присутствовать только в раскрытом результате. На итоговом экране сохраняется последний раскрытый раунд; новые скрытые действия при отключении не раскрываются.

Сервер публикует снимок сразу после изменения и каждые 100 мс. Клиент считает только отображаемые секунды из `deadline - serverTime`; решение об истечении срока принимает сервер. Никаких клиентских временных меток сервер не принимает.

## Фазы и идемпотентность

`waiting → countdown (3 с) → question (12 с) → reveal (5 с) → question/result`.

Два принятых действия завершают раунд досрочно. Если срок уже истёк, сервер сначала рассчитывает раунд с тайм-аутами и только затем рассматривает пришедшую команду. Повторный ход получает ошибку и не изменяет состояние. Устаревшие `matchId` и `round` тоже отклоняются. Для нового матча оба должны отправить `rematch` с текущим `matchId`; после этого номер увеличивается и вся партия сбрасывается.

При отключении часы текущего этапа останавливаются. Принятый ответ сохраняется. После возвращения через `resume` сервер присылает актуальный снимок и продолжает оставшееся время. Через 30 секунд отсутствующий проигрывает подключённому сопернику; если отсутствуют оба — `winner: "draw", reason: "abandoned"` (в интерфейсе «без победителя»). Победа, уже полученная по игровым правилам, не меняется.

## Ошибки

`INVALID_MESSAGE`, `NOT_FOUND`, `ROOM_FULL`, `UNAUTHORIZED`, `ALREADY_JOINED`, `WRONG_PHASE`, `STALE_MATCH`, `STALE_ROUND`, `ALREADY_SUBMITTED`, `NOT_ENOUGH_ENERGY`, `CAPACITY`.

Ошибки действий не разрывают соединение. Неверный JSON также возвращает ошибку. При превышении частоты соединение закрывается кодом 1008; payload больше лимита отклоняется WebSocket-библиотекой.
